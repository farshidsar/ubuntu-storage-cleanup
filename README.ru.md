# Ubuntu Storage Cleanup

Практичный Bash-скрипт для освобождения дискового пространства в Ubuntu: очистка кэша APT, журналов systemd, старых логов, временных файлов, отключённых ревизий Snap, неиспользуемых ресурсов Docker, crash dump-файлов и кэша миниатюр.

## Возможности

- Показывает использование диска до и после очистки
- Очищает кэш APT
- Удаляет неиспользуемые пакеты
- Очищает старые журналы systemd
- Удаляет ротированные и сжатые логи
- Удаляет временные файлы старше 7 дней
- Удаляет отключённые ревизии Snap
- При наличии Docker предлагает очистить неиспользуемые ресурсы
- Сохраняет Docker volumes
- Удаляет старые crash dump-файлы
- Очищает кэш миниатюр пользователей
- Показывает крупнейшие каталоги после очистки

## Требования

- Ubuntu или совместимый Debian-based дистрибутив
- Bash
- права `sudo` / root
- `systemd` для очистки journal
- Snap — необязательно
- Docker — необязательно

## Установка

Клонируйте репозиторий:

```bash
git clone https://github.com/farshidsar/ubuntu-storage-cleanup.git
cd ubuntu-storage-cleanup
```

Сделайте скрипт исполняемым:

```bash
chmod +x ubuntu-storage-cleanup.sh
```

## Запуск

Рекомендуемый вариант:

```bash
sudo ./ubuntu-storage-cleanup.sh
```

Также можно запустить через Bash:

```bash
sudo bash ubuntu-storage-cleanup.sh
```

Без root-прав скрипт завершит работу.

## Очистка Docker

Если Docker установлен, скрипт сначала показывает использование места, затем спрашивает:

```text
Clean Docker unused resources? (y/N):
```

Очистка выполняется только после ввода `y` или `Y`.

Используются команды:

```bash
docker system prune -af
docker builder prune -af
```

Они могут удалить неиспользуемые образы, остановленные контейнеры, неиспользуемые сети и build cache. **Docker volumes сохраняются.**

## Настройка

В начале скрипта можно изменить:

```bash
JOURNAL_RETENTION="7d"
JOURNAL_MAX_SIZE="200M"
MIN_FREE_GB=5
```

> Примечание: `MIN_FREE_GB` сейчас объявлен, но пока не используется логикой очистки.

## Важное предупреждение

Скрипт удаляет файлы. Перед запуском на production-сервере или системе с важными данными внимательно проверьте его содержимое.

Он работает с такими путями, как:

```text
/var/log
/tmp
/var/tmp
/var/crash
/home/*/.cache/thumbnails
/var/cache/debconf
```

Скрипт также удаляет пустые файлы в `/var/log`. Если какой-либо сервис зависит от заранее созданного пустого log-файла, проверьте этот участок перед запуском.
